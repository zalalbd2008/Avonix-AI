# Jobs To Be Done

> "Customers don't buy software because of features. They adopt products to make progress."

---

# Purpose

This document defines the core Jobs-to-Be-Done (JTBD) supported by Avonix AI.

A Job represents the progress a customer wants to achieve.

Jobs remain relatively stable even as features evolve.

This document guides:

- Product Strategy
- UX Design
- Roadmap Planning
- Feature Prioritization
- AI Design
- Success Metrics

---

# JTBD Principles

A Job should:

- Describe an outcome, not a feature.
- Focus on user progress.
- Be measurable.
- Be independent of implementation.
- Be reusable across industries.

---

# Job Structure

Each Job contains:

- Job Statement
- Primary Persona
- Trigger
- Desired Outcome
- Current Pain Points
- Success Criteria
- Related Capabilities
- Related Modules
- KPIs

---

# Job 01 — Launch Website Operations Quickly

## Job Statement

When a new website is connected,

I want to configure everything from one guided workflow,

so I can begin operating immediately.

### Primary Persona

- Organization Administrator

### Trigger

A new website is added.

### Desired Outcome

The website becomes fully operational with minimal manual configuration.

### Current Pain Points

- Multiple disconnected setup steps
- Configuration errors
- Long onboarding

### Success Criteria

- Website connected
- AI configured
- Health monitoring active
- Team invited

### Related Capabilities

- Website Operations
- AI
- Identity

### Related Modules

- Websites
- Workspace
- AI
- Health

### KPIs

- Time to First Value (TTFV)
- Onboarding Completion Rate

# Job Prioritization

Jobs should be prioritized based on:

- Customer value
- Frequency
- Business impact
- Strategic alignment
- Technical feasibility

Feature requests should support an existing Job whenever possible.
